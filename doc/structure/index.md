# consortium-tests repository structure

`consortium-tests` is a **fork**: it vendors the ClusterShell Python suite and
drives the `consortium` Rust rewrite against it, proving the rewrite is
behaviour-preserving. Most of what looks like duplication is deliberate.

## Concepts

- [Vendored upstream](/structure/vendored-upstream.md) — the directories mirrored from ClusterShell, and why their paths are frozen.
- [Rust crates](/structure/rust-crates.md) — `crates/`, the Cargo workspace, and what is a test versus a test library.
- [Tooling and Nix](/structure/tooling-and-nix.md) — `tools/`, `nix/`, and how CI drives all of it.

## Top level

| Path | Role | Movable? |
|---|---|---|
| `tests/` | Vendored ClusterShell Python suite (pytest) | **No** — frozen, see [vendored upstream](/structure/vendored-upstream.md) |
| `lib/` | Vendored `ClusterShell` Python package | **No** |
| `conf/` | Vendored ClusterShell example configuration | **No** |
| `bash_completion.d/` | Vendored shell completions | **No** |
| `setup.py`, `MANIFEST.in`, `packaging/` | Vendored packaging | **No** |
| `TEST_MAPPING.toml` | Generated Python-test to Rust-test map | No — generated by `tools/generate_test_mapping.py` |
| `crates/test-harness/` | `consortium-test-harness`, a Rust **library** (0 tests) | Yes |
| `crates/integration-tests/` | `consortium-integration-tests`, Rust integration tests | Yes |
| `tools/` | CI and scorecard tooling, 0 tests | Yes |
| `nix/fanout-vms/` | The fanout64 microVM benchmark flake | Yes |
| `doc/` | This documentation bundle | Yes |

## Naming rule

Three top-level directories used to be named for the same thing. Only two of
them held tests.

- A **test suite** is named for what it tests: `tests/`, `crates/integration-tests/`.
- A **test library** is under `crates/` with the other crates: `crates/test-harness/`.
- **Tooling** is under `tools/`: `tools/`.

A directory named `harness/` or `test-harness/` that contains no `#[test]` and
no `*Test.py` is a library or a script, and belongs under `crates/` or `tools/`.

## What is deliberately not here

- **No Snowfall Lib.** The flake is a plain `flake.nix` at the repo root with
  one `import ./nix/fanout-vms`. See [tooling and Nix](/structure/tooling-and-nix.md).
- **No `doc-legacy/`.** Removed 2026-09-29. It held the vendored upstream
  ClusterShell `ChangeLog`, stale at v1.9.3 against vendored code at 1.10.1,
  and was referenced by exactly two lines, both `paths-ignore` entries in
  `parity.yml` that skipped CI on changes to it. Nothing read it.
- **No `.config/nextest.toml`.** Removed 2026-09-29. Byte-identical to the
  sibling `consortium` copy and unreachable: `parity.yml` runs
  `cargo nextest --manifest-path ../consortium/Cargo.toml`, so nextest reads
  the *sibling's* config.
